# JP 16.0.0 completeness repairs

The extracted JP 16.0.0 data and retained APKPure XAPK are the mechanics sources.
EN remains at 15.7.0. Existing working-tree data and artwork from the initial
16.0 update were retained. No app export, commit or push was performed.

## Repaired omissions

- Kalisa (159) now publishes all four source stat rows and four backswings
  `[111,111,111,111]`. Its ultra-form name comes from the JP localization;
  the three existing localized names and ultra-form cost are retained.
  Both the name refresh and direct cat generator can reconcile a newly shipped
  ultra form. Validation checks `unitbuy.csv` independently of curated names.
- Combos 3069 (`ビュンビュン`) and 3070 (`骨まで愛して`) are appended to the
  curated data. Source selection now follows the newest EN/JP extraction,
  preferring EN on equal versions. The data has no header: source names must
  use the same row index. Missing names abort before either file is appended.
- Stages preserve EN entries and supplement missing JP identities. All 87
  stage files added between JP 15.7.1 and 16.0.0 match their published enemy and
  battle payloads: 75 prison stages, six Zero Legends stages (`zl_37`), five
  ranking stages (`ranking_29`) and one event stage (`events_436`). The existing
  three-stage prison introduction is also exposed, giving 78 prison stages.
- `colosseum_27` is restored from source. Colosseum maps no longer collapse by
  display name: all 50 supplied maps retain their separate cat restrictions.
  All 1,010 previously published subchapter IDs and the medal catalog remain.
- Enemy IDs 792, 797, 798 and 799 now publish attack frequencies of 5, 41, 31
  and 50 frames, respectively. Values come from their decrypted `e02.maanim`
  resources, counting frame zero and finite loops. The curated ID-based cache
  records animation hashes and source versions. Existing reviewed historical
  frequencies retain priority; other unavailable records still warn.
- Android Studio's standard SDK paths are included in `aapt` discovery on
  Linux/macOS, so source inspection does not silently miss the retained pack
  merely because the SDK is absent from `PATH`.

## Verification

- 204 Python tests pass, including regression fixtures for ultra-form
  truncation, combo row/name alignment, source selection, same-name colosseum
  variants, EN/JP identity merging and enemy animation decryption/timing.
- Cat validation succeeds against JP 16.0.0, explicitly requiring four forms
  for 159. All 888 unit IDs and 800 enemy IDs are retained.
- Animation dry-run: zero changed paths, no pending source packages.
- Backswing dry-run: zero changed units. The 66 unavailable forms retain null
  values and visible warnings, including duplicate third-form placeholders
  877–886; no animations or forms were fabricated.
- Repeating all affected pipeline steps leaves public data identical apart
  from update timestamps, and leaves curated inputs byte-identical.
- Stage source coverage: 87/87 new files checked directly; no previous
  subchapter IDs lost. Final catalog: 23 chapters, 1,045 subchapters and
  5,373 root stages. `git diff --check` passes.

## Thumbnail compatibility

Units 882–886 declare a third stat row identical to their evolved form and
repeat the evolved name. Their source pack supplies only first/evolved
portraits. Added `uni882_s00.png` through `uni886_s00.png` as byte-identical
aliases of the corresponding evolved portraits, matching the existing
877–881 compatibility convention. The aliases are public and copied to the
configured app drawable directory. Stat rows and animation omissions remain
unchanged. Summoned spirits 876 and 887 still have no dictionary portrait in
the source; no portrait is invented for them.
